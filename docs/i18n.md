# 插件多语言维护

## 资源与语言来源

`ui/src/i18n/locales/` 中每种语言独立维护一个 JSON 文件：
`az`、`en`、`es`、`it`、`ja`、`ko`、`pt-BR`、`tr`、`zh-CN`、`zh-TW`。
英文是键结构基准和未知语言的回退；繁体中文使用独立文案，不在运行时转换简体。

`ui/src/i18n/locale.ts` 统一规范化 DBX 的 locale（下划线、地区和中文书写体系别名）。
`host-language.ts` 接收宿主启动值、SDK 事件、`dbx-plugin-env` 事件，并兼容仅提供 locale getter 的旧桥接。
外观偏好的历史语言和跨窗口存储事件不能覆盖 DBX 当前语言。插件菜单可临时切换语言；宿主语言变化时再次跟随宿主。
日期格式、相对时间和图表时间使用相同的当前 locale。

## 新增或修改文案

1. 使用 `useTranslation()` 将显示文案接入 UI，Hook 只放在组件顶层。
2. 同步维护 10 份资源的相同结构和键，保留 `{{name}}`、`${value}`、`%s` 等插值。
3. 保留 Kubernetes Kind、命令、字段名、资源数量示例、URL、快捷键和格式标记。
4. 按使用场景校对。按钮使用操作动词；例如“清空”不能译作颜色“明亮”，Job 不能译作求职。
5. 日期文案不要写死英文或只判断中文/英文。

## 检查与构建

```sh
cd ui
pnpm run i18n:check
pnpm run i18n:report
pnpm run test:i18n
pnpm test
pnpm run type-check
```

生产构建自动执行语言检查。检查范围：精确键结构、字符串类型、Unicode、占位符数量、HTML 标记、反引号、资源数量示例、Kind、未翻译的英文值和繁体中的简体专用字。
英文同形词和技术标识在 `scripts/check-i18n.mjs` 中显式列出；不要扩大豁免来隐藏缺失翻译。
自动检查只能发现结构和典型问题，不能替代语义校对及页面布局检查。

回到仓库根目录运行 `make dbxp`，会先构建再打包。构建和安装包共用 `ui/dist` 产物。

## 机器初译工具（仅维护时使用）

本次获得用户明确授权后，通过 Google 翻译服务处理 `en.json` 与 `zh-CN.json` 的静态 UI 文案。
`scripts/translate-locales.py` 不参与运行时和构建，没有密钥依赖。它只发送静态字符串，先保护技术标识、插值和格式，再验证返回值。
缓存保存在被 Git 忽略的 `tmp/i18n/`。

后续使用外部翻译服务前，应确认相应文案允许发给该服务。已有校对值应保留：

```sh
python3 scripts/translate-locales.py --missing-only es it pt-BR az tr ja ko zh-TW
```

工具产物仍需校对；完整重生成会覆盖人工校对值。不要在构建或 CI 中自动调用在线翻译。
